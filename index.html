Plain MCP or Smart MCP?

Plain MCP gives your coding agent tools: run SQL, list tables, query a metric. Your agent's model does the reasoning. Smart MCP tools run the platform's own LLM behind the call, so a second model plans and writes the SQL, and it bills separately. This index shows which you get on 82 data platforms, whose model runs it, and how to add business context while staying on Plain MCP.

Where the reasoning happens

The same question, asked from a coding agent. Left, the agent; right, the data platform's own console showing what arrives over MCP. Press play on each in turn. With Plain MCP, your client's model writes every query and reads the rows. With Smart MCP, the tool hands the question to the platform's own model, which writes the SQL for you.

Plain MCP is not the weak option. Give it a semantic layer and it returns governed numbers with one model. The matrix shows which platforms let you do that and the Add context tab shows how.
Smart MCP earns its cost when the person asking has no AI client of their own, or when you want the vendor to own answer quality on a curated dataset. Check the Smart MCP models tab for whose model it is.

Rollout path

  1. Weeks 1 to 4: prove it read-onlyOne platform, Plain MCP, a read-only role, column comments and audit logs. Write 30 real business questions with known answers as your eval set.
  2. Months 2 to 3: govern the numbersExpose the semantic layer as tools, add per-user OAuth, masking policies and a gateway. Track tool calls and cost per team. Rerun the eval set on every change.
  3. Then: add Smart MCP where it winsOffer platform agents to business users with budgets. Run the same eval set through Smart MCP and Plain MCP and keep whichever is more accurate per domain.

Architect's checklist

  1. IdentityPer-user OAuth so row and column policies apply to the person asking, not a shared service account.
  2. Least privilegeRead-only roles, tool allow-lists per persona, no write tools for analytics agents.
  3. Untrusted tool outputRows and documents can carry prompt injection. Treat tool results as data, and never let them trigger write or send tools without a human.
  4. Cost guardrailsBudgets and alerts on platform AI services, row and byte caps on queries, per-team usage views.
  5. Residency and termsCheck cross-region inference settings on each platform and zero data retention terms with every model provider in the path.
  6. Evals and auditA fixed question set with expected answers, run on every model, prompt or semantic layer change, and a log of every tool call.

Whose model runs inside Smart MCP tools

When a Smart MCP tool runs, your question and often your rows reach the platform's model as well as your client's. Counts cover tools reachable over MCP, as documented on 2 November 2026.

"Vendor model, not named" means the docs describe an AI tool without naming the provider. Ask before you route regulated data through it. "Vendor menu" means several providers are on offer and either you or the vendor picks; check which one your tenant uses.

How Smart MCP is billed

The MCP server is usually free. Plain MCP tools cost compute; Smart MCP tools add an AI charge, and your client's tokens don't go away.

What your model provider sees

Every byte a tool returns goes into your client's context and on to its provider. Smart MCP doesn't change that: its answer still comes back to your client, and the platform's model sees the data on the way.

Q: How many active customers in Chennai?
→ list_tables, describe_table dim_cust
→ SELECT * FROM dim_cust LIMIT 20
names, phones, emails now in context
→ SELECT DISTINCT cust_flg_3 …
guessing what "active" means
→ invents a definition; finance disagrees
Where the platform's model runs matters too. Snowflake Cortex routes to other regions when CORTEX_ENABLED_CROSS_REGION allows it. Fabric data agents need cross-geo processing switched on in regions without Azure OpenAI. Check Google's conversational analytics endpoints against your residency rules.

Controls, in the order they pay off

  1. Metadata before rowsWrite column comments and expose descriptions, glossary terms and metric definitions as tools, so the agent never samples a column to learn what it means.
  2. Profile inside the warehouseA profile_column tool returns counts, null share, min, max and masked top values. The shape without the records.
  3. Query through the semantic layerMetric queries return one aggregate row, not twenty customer records.
  4. Enforce in the databaseA read-only role for the MCP connection with masking and row access policies. A prompt can be ignored; a masking policy can't.
  5. Cap what comes backRow limits, byte limits and timeouts on the server or role, not left to the agent.
  6. Contract and routingZero data retention terms with your client's provider, or route sensitive schemas to a model you host.

What counts as Smart MCP

A tool on the vendor's MCP server that sends your question to a model the vendor runs or you configure on the vendor side. AI features that exist only in the product's own UI are marked separately, because a coding agent never calls them.
